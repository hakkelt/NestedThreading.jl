API reference

NestedThreading — Module
NestedThreading

Coordinate a shared CPU thread budget across independently-threaded libraries (BLAS, FFTW, Polyester, NFFT, …) so that an outer parallel loop does not oversubscribe the machine with inner threading — Julia's answer to Python's threadpoolctl.

The entry points are @budgeted_threads / @budgeted_batch for loops, @budgeted for a loop construct you want to keep exactly as written, and with_threads_disabled / with_threads_enabled for call sites that are not loops. Libraries register themselves through package extensions; see register_pool! to add one this package does not ship.

Budgeting is one half of the problem. The other is that a library's workers can go on occupying Julia's threads after its own parallel region has ended, so that a Threads.@threads region opened next waits for them instead of running on them — 38x on the measurement in register_pool!. The loop macros here handle that for themselves; quiesce_foreign_pools is the same thing for a parallel region written by hand.

Loop macros

NestedThreading.@budgeted — Macro
@budgeted <parallel-loop>

Wrap an already-chosen parallel loop so that its body runs with inner threaded libraries limited to max(1, capacity() ÷ length(range)) threads, or 1 for an iterator of unknown length (see NestedThreading.capacity). The loop construct is emitted unchanged — this macro never decides whether to parallelize, only what budget the workers get.

@budgeted Threads.@threads for j in 1:num_threads
    mul!(view(out, :, j), op, view(inp, :, j))
end

Accepts any chain of macros ending in a single for x in range loop, so Threads.@threads :static for, @inbounds Polyester.@batch for, and @batch minbatch=64 for all work. The range expression is hoisted into a temporary and evaluated exactly once. A chain containing @batch automatically excludes the :polyester pool, since there the loop being budgeted is itself the Polyester consumer. The expression evaluates to nothing.

See also @budgeted_threads, @budgeted_batch.

source
NestedThreading.@budgeted_threads — Macro
@budgeted_threads [schedule] [threads = <bool>] for x in range ... end

Threads.@threads over range with an automatic inner thread budget, plus a runtime switch for whether to parallelize at all.

Every argument before the loop other than threads = ... is passed to Threads.@threads unchanged and in order; in practice that is the schedule (:dynamic, :static or :greedy): @budgeted_threads :static threads = flag for .... Any other name = value option is an error at expansion, since Threads.@threads takes no keyword options.

  • threads = true (the default when omitted) runs Threads.@threads with the body's inner libraries limited to max(1, capacity() ÷ length(range)) threads, or 1 for an iterator of unknown length.
  • threads = false runs a plain sequential loop with inner libraries limited to a single thread, on the assumption that a caller who switched threading off did so because concurrency is happening somewhere else. The schedule does not apply to it.

Body-level macros such as @inbounds may wrap the loop; they are rebuilt around the emitted Threads.@threads. A macro that parallelizes the loop itself (Threads.@threads, Polyester.@batch, @distributed, …) is rejected at expansion, since this macro emits one already — use @budgeted to budget a parallel loop you have written yourself. @budgeted is also the way to combine this with a macro that insists on being handed a bare for loop, such as @simd. The expression evaluates to nothing.

julia> squares = zeros(Int, 4);

julia> @budgeted_threads :static for i in 1:4
           squares[i] = i^2
       end

julia> squares
4-element Vector{Int64}:
  1
  4
  9
 16

julia> parallel = false;

julia> limits = zeros(Int, 4);

julia> @budgeted_threads threads = parallel for i in 1:4
           limits[i] = NestedThreading.thread_limit(:blas)   # the inner budget
       end

julia> limits
4-element Vector{Int64}:
 1
 1
 1
 1

NestedThreading.@budgeted_batch — Macro
@budgeted_batch [options...] [threads = <bool>] for x in range ... end

Polyester @batch over range with an automatic inner thread budget and the same threads = switch as @budgeted_threads.

Every other argument before the loop is passed to @batch unchanged and in order, so its options combine with the switch: @budgeted_batch minbatch = 64 threads = flag for .... The sequential threads = false loop ignores them.

The calling module must have Polyester available (import Polyester), since the expansion emits Polyester.@batch. The :polyester pool is excluded from the budget scope so that the generated @batch loop is not disabled by its own restriction.

As with @budgeted_threads, a chain that already parallelizes the loop is rejected at expansion. The expression evaluates to nothing.

julia> import Polyester

julia> total = Threads.Atomic{Int}(0);

julia> parallel = true;

julia> @budgeted_batch minbatch = 2 threads = parallel for i in 1:8
           Threads.atomic_add!(total, i)
       end

julia> total[]
36

Scopes

NestedThreading.with_threads_disabled — Function
with_threads_disabled(f; exclude = (), only = nothing)

Run f() with every registered threaded library limited to a single thread and return f()'s value. Equivalent to with_thread_limit(f, 1; exclude, only); see with_thread_limit for exclude and only. Use at call sites that are not a plain for loop — a @sync/@spawn block, or a single call gated on a Bool field.

source
NestedThreading.with_threads_enabled — Function
with_threads_enabled(f; exclude = (), only = nothing)

Run f() with every registered thread count set to capacity and return f()'s value. Equivalent to with_thread_limit(f, capacity(); exclude, only); see with_thread_limit for exclude and only.

Calling f() without any scope leaves each count where it is; this scope raises the counts, so it turns on a library that defaults to off (it sets NFFT._use_threads[] = true, for instance). That is what a call site with an explicit threaded = true switch needs.

Any outer restriction still clamps it, so calling it inside a saturated batch loop is safe and does nothing. Since its limit is capacity(), it never calls a guard itself; a guard runs only when another open restriction holds the limit below capacity() at entry.

NestedThreading.with_thread_limit — Function
with_thread_limit(f, n::Integer; exclude = (), only = nothing)

Run f() with every registered threaded library limited to n threads, and restore the previous state afterwards, also when f() throws. Return f()'s value. An n below 1 is raised to 1.

The limit applied to a pool is the minimum over every restriction currently active in the process that applies to that pool, so

  • nesting can only narrow an outer restriction, never widen it: an inner with_thread_limit(f, 8) inside an outer with_thread_limit(g, 1) still runs at 1;
  • concurrent scopes cannot corrupt each other's bookkeeping: the counts are snapshotted when the first scope opens and restored when the last one closes.

By default a restriction applies to every registered pool, thread counts and guards alike (see register_pool!). Two keywords narrow that:

  • exclude: pool names this restriction does not apply to. Naming a pool leaves its thread count and its guard alone. A name no pool has registered is not an error, so a caller may exclude a pool whose package is not loaded in this session.
  • only: when given, the restriction applies to these pools and no others. A pool left out is left alone entirely: unless another active scope restricts it, it keeps the value it had before this scope opened, even when that is above this scope's limit. This is how a call site asks for, say, serial BLAS; a denylist would have to name every other pool and would miss any registered later.

Each takes a single pool name or a collection of them: exclude = :polyester, only = (:blas, :mkl) and only = [:blas, :mkl] all work. An element that is not a Symbol throws an ArgumentError.

julia> using LinearAlgebra

julia> with_thread_limit(1; only = :blas) do
           BLAS.get_num_threads()
       end
1

julia> with_thread_limit(1) do
           with_thread_limit(8) do    # nesting only narrows
               BLAS.get_num_threads()
           end
       end
1

See also with_threads_disabled, with_threads_enabled, with_thread_default, thread_limit.

Extended help

Nested limits that change nothing

A limit nested in an enclosing one, on the same task or on a task spawned inside it (such as a @budgeted_threads worker), that already holds every pool it covers at or below n is not entered: it could change nothing, so f() runs directly, without setting the pools or running the guards, which keeps such a scope to microseconds. The check still takes the registry lock once. A scope open on an unrelated task never counts. The check relies on the enclosing scope outliving f(), which a task spawned inside a scope and never waited for does not guarantee. It needs ScopedValue (Julia 1.11 and later); on Julia 1.10 every scope is entered.

Guards

Guards are invoked only when the limit that applies to them is below capacity, and they receive that limit. Polyester's guard switches Polyester off entirely rather than limiting it proportionally, because a partial limit measured far worse in the saturated regime; see register_pool!. @budgeted_batch uses exclude = (:polyester,) because there the outer loop is itself the Polyester consumer.

Guards are decided once, at entry

Counted pools follow the applied minimum for as long as the scope is open — another task narrowing the limit lowers them immediately. Guards cannot work that way: a guard is a lexical wrapper around f(), so whether it runs is decided from the limit at entry and cannot be revised afterwards.

So a scope that enters while nothing is restricted runs its body unguarded even if a concurrent task restricts the process meanwhile: its BLAS and FFTW counts drop, but a nested Polyester loop inside it can still spawn workers. The other direction is safe — a scope that entered restricted stays guarded for its whole body even after the other scope exits. Only the guarded libraries are affected, and only for scopes that opened unrestricted; if it matters, open the restricting scope before spawning the tasks rather than from inside them.

A limit of `capacity()` raises, it does not merely permit

The limit is applied to every counted pool this restriction applies to unconditionally, so a scope whose budget works out to capacity — with_threads_enabled, or a loop with a single item — sets those pools up to that value for its duration, even past a lower count the caller had configured (BLAS.set_num_threads(2), say). The original counts are restored on exit like any other scope. This is what makes with_threads_enabled able to turn NFFT on; if a hand-tuned lower count must be preserved, do not open an unrestricted scope around it — or exclude/only it out of one.

A pool named in exclude, or left out of only, is not "permitted" either way: as long as nothing else currently active restricts it, it keeps whatever value it already had, not the value this scope requested.

Process-global state

BLAS and FFTW thread counts are process-global with no per-task scoping. Taking the minimum over all active scopes is deliberately conservative: while any task is restricted, unrelated concurrent tasks are restricted too. That never oversubscribes, but it does mean a long-lived restricted scope throttles the whole process. This is a limitation of the underlying C libraries, not something this package can solve.

NestedThreading.with_thread_default — Function
with_thread_default(f, n::Integer; exclude = (), only = nothing)

Run f() with every registered threaded library at n threads by default: the count it runs at unless a with_thread_grant nested inside says a particular call is worth more. Returns f()'s value.

This is the scope to open around a whole computation whose calls into a library are mostly too small to benefit from its threads, but some of which are not. A hard with_thread_limit cannot express that: nothing nested inside it can widen past it, so the few large calls would run serial too.

Soft defaults combine with each other by minimum and yield only to a grant: a hard limit open around or inside a soft default still clamps it, and a soft default of n below a hard limit of m > n runs at n, since the limit is a ceiling and not a request.

using LinearAlgebra
a, x, y = 2.0, rand(1000), rand(1000)
big = rand(2000, 2000)

with_thread_default(1; only = (:blas,)) do     # small BLAS calls: serial
    for iteration in 1:100
        axpy!(a, x, y)                          # BLAS at 1 thread
        with_thread_grant(NestedThreading.capacity(); only = (:blas,)) do
            svd!(big)                           # BLAS at every thread
        end
    end
end

See with_thread_limit for exclude, only and what is process-global.

NestedThreading.with_thread_grant — Function
with_thread_grant(f, n::Integer; exclude = (), only = nothing)

Run f() with every registered threaded library allowed n threads despite any soft default in force (with_thread_default), for a call that is known to be large enough to be worth threading. Returns f()'s value.

A grant overrides soft defaults but never a hard limit: inside a with_thread_limit(g, 1) — a worker of a saturated outer parallel loop, say — a grant does nothing. It also never raises a pool past the count the process runs it at when no scope is open: it restores threading that a soft default took away, but it does not add threads a caller turned off by hand with, e.g., BLAS.set_num_threads(1). Several grants open at once combine by maximum.

When a grant closes and a pool's count goes down as a result, the pool's park hook runs (see register_pool!), so that a library whose idle workers would otherwise go on spinning (OpenBLAS) releases them. That costs about a millisecond for OpenBLAS, counting the pool's restart at the next grant, so a grant belongs around a call worth several milliseconds. Decide whether a call is that large before opening the scope: a scope that ends up doing nothing still costs a lock and a pass over the registry.

using LinearAlgebra
matrices = [rand(n, n) for n in (50, 2000, 80)]

with_thread_default(1; only = :blas) do
    for A in matrices
        if size(A, 1) >= 1000                  # large enough to be worth threading
            with_thread_grant(() -> svd!(A), NestedThreading.capacity(); only = :blas)
        else
            svd!(A)
        end
    end
end

See with_thread_limit for exclude, only and what is process-global.

NestedThreading.thread_limit — Function
thread_limit(name::Symbol) -> Union{Int,Nothing}

Return the hard limit the scopes enclosing the calling task put on pool name: the smallest n among the with_thread_limit scopes (and so with_threads_disabled, a limit of 1) that apply to it and that this task runs inside – opened by it, or by a task it was spawned from while the scope was open – or nothing when there is none. A scope open on an unrelated task does not count: it may close at any moment. Polyester's workers are such tasks, so inside a Polyester.@batch body this reports nothing on every worker except the calling task.

Soft defaults (with_thread_default) and grants (with_thread_grant) are not counted, since neither bounds the count. The name does not have to be registered.

with_thread_limit already uses this to skip a nested limit that could change nothing, so a caller needs it only to ask about one pool in particular – to skip a scope where a limit on that pool alone is in force, say.

On Julia 1.10, which has no ScopedValue, enclosing scopes are not tracked and this always returns nothing: a caller that acts on it then enters its scope, as it would anyway.

julia> NestedThreading.thread_limit(:blas) === nothing   # no scope open
true

julia> with_thread_limit(2; exclude = :polyester) do
           NestedThreading.thread_limit(:blas), NestedThreading.thread_limit(:polyester)
       end
(2, nothing)

NestedThreading.reset_thread_counts! — Function
reset_thread_counts!()

Set every registered thread count back to the value it had when its library registered, both now (if no scope is open) and as the value the last scope to close restores. This is the process-wide escape hatch for code that only ever runs one thing at a time and wants every library back at the count it started with, typically unrestricted, after something lowered it by hand (BLAS.set_num_threads(1), say).

Scopes still win while they are open; this only changes what the process returns to when nothing is open. It is not scoped and has no inverse.

Registry

NestedThreading.register_pool! — Function
register_pool!(name::Symbol; get = nothing, set = nothing, guard = nothing,
               quiesce = nothing, park = nothing)

Register the threaded library name together with every control it offers, in one call. NestedThreading's own package extensions use it, and so can any package that adds a library this package does not ship an extension for:

function __init__()
    NestedThreading.register_pool!(:mylib; get = MyLib.get_threads, set = MyLib.set_threads)
end

The keywords are the controls a library can have; pass the ones it has:

  • get, set: a persistent thread count, read as get() and written as set(n::Int), such as BLAS.get_num_threads/BLAS.set_num_threads. The first scope to open snapshots the count, every scope change applies the effective limit to it, and the last scope to close restores the snapshot.
  • guard: a scoped switch, called as guard(f, n::Int), that runs f() with the library limited to n threads and returns f()'s value. See "Guards" below.
  • quiesce: called as quiesce() right before this package opens a parallel region on Julia's own scheduler, to make the library's idle workers let go of Julia's threads. See "Quiescing" below.
  • park: called as park() after a with_thread_grant scope closes and lowers this library's count, to make the workers it no longer uses release the cores they are spinning on. Needs get/set. See "Parking" below.

A library that offers only a scoped switch registers a guard; one whose idle workers hold on to Julia's threads or to cores adds quiesce or park:

NestedThreading.register_pool!(:mylib; guard = (f, n) -> MyLib.with_workers(f, n),
                               quiesce = MyLib.release_idle_workers)
NestedThreading.register_pool!(:myblas; get = MyBLAS.get_threads, set = MyBLAS.set_threads,
                               park = MyBLAS.stop_idle_workers)

Return nothing. A hook that throws later, during a scope, is not fatal; see "Hooks that throw" below.

Registration is checked strictly. It throws an ArgumentError for a name that is already registered, for get without set or set without get, for park without get/set, for no control at all, and when get() does not return an Integer. An exception thrown by get() at registration, or by set when a scope is open (see below), propagates unchanged. A failed call registers nothing.

Registration is expected to happen at load time (__init__), but an extension may be loaded while some task has a scope open. A newly registered count then takes its current value as its restore value and gets the restriction in force at once, so the last scope to close restores it with everything else. A guard registered while a scope is open is not applied to that scope, only to those opened afterwards.

Extended help

Counts first

Prefer get/set whenever the library has an imperative setter, even a boolean one. A count goes through this package's refcounted snapshot/restore and is therefore safe under concurrency, whereas a guard that saves and restores a global itself reintroduces the very interleaving bug this package exists to fix. A boolean switch maps onto a count; the NFFT extension shows the pattern. guard is for APIs like Polyester's, which are reservation-based and have no imperative form.

Guards

A guard is only ever called with n < capacity(); an unrestricted scope skips guards entirely. Most libraries with only a scoped switch can only be switched fully off, which is the right default: a partial limit was implemented for Polyester (which supports one) and measured 320x worse in the saturated regime, because at high thread counts a nested parallel loop is catastrophic however few workers it gets. See the PolyesterWeave extension for the numbers. n is passed anyway so a library with a genuinely proportional control can use it.

A guard must act for the whole process while it is held, not only for the calling task: Polyester's reserves its workers, which every task then finds taken. A hard limit nested in one that already covers this library does not call the guard again (see with_thread_limit), so the enclosing scope's guard is all that restricts a nested call on another task.

The guard receives an arbitrary caller closure, whose type is not known until the call site, so one runtime dispatch per guarded scope is inherent. It happens once per scope, not once per loop iteration.

Hooks that throw

A hook that throws once registered is not fatal. When a get, set, park or quiesce call throws, it is skipped: every other pool is still set, restored, parked and quiesced, the scope's bookkeeping stays consistent, and the scope returns its body's value or rethrows its body's exception as if nothing had happened. A count whose get throws keeps the value it was last restored to. A guard that throws before calling f, or returns without calling it, is skipped and f() runs without it; one that throws after f() has returned still gives back f()'s value; and when f() itself throws, that exception is what propagates, whatever the guard throws while unwinding. The first failure of each pool is logged with @warn, later ones at debug level.

Quiescing

Some libraries' workers keep occupying Julia's threads after one of their parallel regions has finished. Polyester is the case this exists for. Its workers are Julia tasks that spin on a state word for about 2^20 pause() iterations before parking, so for the whole of that window the Julia threads they sit on are busy. A Threads.@threads region opened in that window does not get those threads; it waits for them. Measured on an AMD EPYC 7352, 8 Julia threads, Julia 1.13.0, 2026-09-21, with an empty loop body:

Threads.@threads, in a process that has never run a `@batch`     5.7 us
Threads.@threads, after one `@batch` has run                   219.9 us
Threads.@threads, after `@batch` + quiesce                      18.6 us
the quiesce call itself                                          0.1 us
Polyester.@batch, after a quiesce                                5.0 us

A 38x penalty, removed for a tenth of a microsecond, and re-waking the workers for the next @batch costs nothing measurable. See the PolyesterWeave extension and https://github.com/JuliaSIMD/Polyester.jl/issues/82.

Unlike a guard, quiesce is not scoped and takes no thread count: it is a one-shot "release the threads now" with no paired restore, because the library re-acquires what it needs at its next region on its own. The loop macros call every registered quiesce themselves, except Polyester's own around a Polyester.@batch loop, whose workers run on Julia's threads too.

Parking

OpenBLAS is the case park exists for. Lowering its thread count does not stop the workers it no longer uses: they go on spinning for OPENBLAS_THREAD_TIMEOUT (by default 2^28 cycles, about 0.1 s) before they sleep, on cores the caller's own threads now want. A grant that raises BLAS for one factorization inside a solve that otherwise runs it serial would leave that spin behind after every factorization.

park is called after the count has already been lowered, with the registry lock held: no grant can open and start using the workers while they are being released. It must therefore not wait on another task that opens a scope. It is not called when a plain with_thread_limit or with_thread_default scope closes: those lower nothing that was not lowered before they opened.

It is not called either while a hard limit strictly between 1 and capacity is open around the library. Such a limit is what @budgeted_threads opens for a loop with fewer items than threads, whose other workers may be inside a threaded call to the same library, at the count a grant raised, when this grant closes.

Calls that bypass the scopes

The lock only orders park against other scopes. A task that calls into the library with no scope of its own, at a count a grant raised, may still be inside that call when the grant closes and park runs. Whether that is safe is the library's business; for OpenBLAS it is not, which is why its hook is skipped under a partial limit.

NestedThreading.thread_pool_info — Function
thread_pool_info() -> Vector{<:NamedTuple}
thread_pool_info(name::Symbol) -> Union{NamedTuple, Nothing}

Describe every registered library, in registration order, as one NamedTuple each, or only the library registered as name. Each has these fields:

  • name::Symbol: the name it was registered under (see register_pool!).
  • has_count, has_guard, has_quiesce, has_park: which controls it registered (get/set, guard, quiesce, park), each a Bool.
  • current: its thread count right now, as its get() reports it.
  • unrestricted: the count it returns to when no scope is open: the snapshot taken when the first open scope entered, or current when none is open.
  • effective: the count the open scopes apply to it, or current when none is open.

The three counts are Ints, or nothing for a library without get/set. current is also nothing when get() throws (see register_pool!), and so are unrestricted and effective if no scope is open then. The result is a snapshot taken under the registry lock; it does not change as scopes open and close.

thread_pool_info(name) returns nothing for a name no library has registered (logged at debug level), so a caller can ask about a library whose package may not be loaded.

# The thread count of every library that has one, right now:
[p.name => p.current for p in thread_pool_info() if p.has_count]

# The count the open scopes apply to BLAS, or `nothing` if BLAS has no count:
info = thread_pool_info(:blas)
info === nothing || info.effective

NestedThreading.capacity — Function
capacity() -> Int

Return the number of worker threads a parallel loop is assumed to be able to occupy. The loop macros divide it among their workers, and scopes treat a limit of capacity() as unrestricted.

Defined as Threads.threadpoolsize(). This is exact for Threads.@threads and an approximation for Polyester's @batch; it is a single function so that assumption lives in one place.

Releasing Julia's threads

NestedThreading.quiesce_foreign_pools — Function
quiesce_foreign_pools()

Call every registered quiesce hook (see register_pool!), so that a region about to be opened on Julia's own scheduler can actually use Julia's worker threads. Return nothing.

The loop macros call this for themselves. Around a Polyester.@batch loop they skip only Polyester's own hook, since there the Polyester pool is the loop. Call it directly before a hand-written Threads.@threads or @spawn region that does not go through those macros:

import Polyester

Polyester.@batch for i in eachindex(a)
    a[i] = f(a[i])
end
NestedThreading.quiesce_foreign_pools()   # Polyester's spinning workers let go of the threads
Threads.@threads for i in eachindex(b)
    b[i] = g(b[i])
end

It is a plain call with no paired restore, costs about 0.1 µs with Polyester loaded, and is a no-op when nothing is registered. It is safe to call when no foreign region has run: parked workers stay parked.
